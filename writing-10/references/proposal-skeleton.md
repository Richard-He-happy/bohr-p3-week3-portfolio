# 开题方案骨架：判据、字段与兜底文案（proposal-skeleton.md）

本文件同时是「人读的检查表」和「程序读的模板源」。`scripts/draftkit.py` 只认 `<!-- KEY:名字 -->` 标记块；
块的先后顺序无关紧要，但**两个标记块之间不能夹正文**（块会一直延伸到下一个标记），
块内格式是固定的：表头块一行 `|` 分隔的列名，行模板块每行一条记录，兜底文案块若干行纯文本。
所以改措辞、改表头、换兜底句子都只改这里，脚本不用动。

> 适用：开题报告、研究计划书、立项申请中的研究方案章节。
> 不适用：文献综述、语言润色、投稿信、结题报告。

## 人读部分一：要素检查表

| 要素 | 至少要写到什么程度 | 反例（一眼看出不合格） |
|---|---|---|
| 研究背景与缺口 | 按"已知 → 未知 → 待验证"递进；缺口必须由所引材料证据直接指出 | 把领域综述抄一遍；缺口和本研究没有因果关系 |
| 研究问题 | 1 到 3 条；每条有假设，并说明"出现什么观测就推翻它" | 只写"研究 X 的机理与应用"，数据无法否定 |
| 研究目标 | 与问题编号一一对应，含指标、样本、对照、判定时点 | 目标和问题各写一套，互不对应 |
| 技术路线 | 步骤化：输入 → 操作 → 输出 → 依赖关系；方法出自材料 | 方法空泛；步骤之间没有依赖 |
| 阶段计划 | 全部落在给定周期内；里程碑带交付物、完成判据与关键路径标记 | 只写月份，没有交付物和判据 |
| 风险与备选方案 | 覆盖数据获取、方法可行性、进度、伦理合规四类；每条含触发信号、影响、备选、决策时点 | 一句"存在一定风险"就结束 |
| 预期成果 | 与问题编号对应，写明验证方式与判据 | 把设想写成已获结果，或承诺材料外成果 |

## 人读部分二：证据口径

- 每个关键论断配三件套：材料编号（`M1` 这类）、段落定位（`p3` 表示该材料第 3 段）、原文逐字片段。
- 核验方式是"去掉空白后逐字比对"。命中不了的只能降级为提醒并登记进 `pending_human`；不允许改写原文来凑命中。
- 数字、单位、样本量、周期写法必须和材料一致；计划里新设的目标值要标"计划值"并说明依据。

## 人读部分三：状态判定（由脚本给出，人不要手改）

| 状态 | 判定条件 |
|---|---|
| `ok` | 七要素齐全、问题有判伪条件与阈值、里程碑 ≥3 条、风险 ≥4 条且 ≥3 类、引文命中 ≥90%、工作稿由 Agent 撰写 |
| `partial` | 以上任一条不满足，或用了模板兜底，或存在要素级错误 |
| `insufficient_evidence` | 材料在，但解析不出文本 |
| `input_error` | 一份输入材料都没有 |

## 维护提示

- 新增一条表头：先加 `thead.xxx` 标记块，再在对应的 `spec.*` 块引用它。
- 新增一个兜底句：加 `fb.xxx` 标记块，并在 `draftkit.template_draft()` 里取用。
- 改校验阈值：不要动本文件，去改 `draftkit.inspect_draft()`。
